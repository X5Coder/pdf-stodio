# PDF Studio — السكيل الأساسي العام (محرر مشاريع PDF، متوافق مع أي AI Agent)

> **الفكرة العامة (كل شيء يخدم عليها):** هذا النظام يعمل كـ **محرر/منظّم لمشاريع PDF**.
> أنت (أو المستخدم) تحمّل/تحدد مشروعًا، وتُعطيه لأي AI Agent مع **التصميم/السكيلز/التعليمات** الخاصة بذلك المشروع، ثم يطلب منه بناء الصفحات أو استكمالها — والـ Agent يطبّق ما أُعطي له داخل إطار المشروع.
> لا يوجد ستايل/ديزاين مفروض عالميًا على كل المشاريع. التصميم يجي من **سكيلات المشروع** أو من التعليمات اللي يحددها المستخدم للمشروع.

## نقطة دخول لأي Agent (OpenCode, Cursor, Copilot, Claude, Gemini, Windsurf, Aider, أي أداة)
1. اقرأ هذا الملف: `projects/PROJECT_SYSTEM_BASE.md`
2. اقرأ `AGENTS.md` و`PROJECT_MAP.md`
3. إذا تم تحديد مشروع (`projects/<project-id>`): اقرأ `project.json` ثم **كل ملفات `.md`** داخل `projects/<project-id>/skills/` قبل التنفيذ
4. نفّذ المطلوب داخل المشروع المحدد، مع الحفاظ على فصل المشاريع الكامل وإخراج **PDF صالح**

## البنية القياسية (فصل كامل لكل مشروع)
```text
projects/
├── PROJECT_SYSTEM_BASE.md          # السكيل الأساسي العام للمحرر/النظام
└── <project-id>/                   # مشروع مستقل بالكامل
    ├── project.json                # إعدادات/بيانات المشروع
    ├── fonts/                      # خطوط المشروع فقط
    ├── skills/                     # سكيلز/تعليمات/تصميم المشروع (.md) — تُقرأ كلها
    │   ├── README.md
    │   └── *.md                    # ضع هنا التصميم، القواعد، المراجع، تعليمات البناء
    └── pages/                      # صفحات المشروع
        └── pageNN/
            ├── page.jsx            # كود الصفحة
            └── images/             # صور الصفحة
```

### إعدادات على مستوى المشروع (`project.json`) — إلزامي توضيح اتجاه الصفحات
- **لازم يحدد اتجاه صفحات المشروع** في `project.json` باستخدام `orientation`:
  - `"orientation": "portrait"` (طولي)
  - `"orientation": "landscape"` (عرضي)
- `preset` (مثل: `slide`, `a4`, `a4l`, `letter`, `letterl`) يحدد مقاس/نمط الصفحة، ويمكن استخدامه مع `orientation` (ويُفضّل أن يكونا متوافقين لتجنب الالتباس).
- عند إنشاء مشروع جديد أو تعديل مشروع، تأكد أن `orientation` محدد بوضوح لأن المعاينة/التخطيط على مستوى المشروع تعتمد عليه.
- `dir`/`lang`/`theme` وغيرها إعدادات خاصة بالمشروع.

## قواعد الفصل
- كل مشروع مستقل: `fonts/` + `skills/` + `pages/` + `project.json`.
- ممنوع مشاركة خطوط/سكيلز/صور/كود صفحات بين المشاريع.
- **التصميم/الستايل ليس عالميًا**: يوضع داخل `projects/<project-id>/skills/` (أو ضمن ملفات المشروع) حسب ما يريده المستخدم/المشروع.

## سير العمل (Editor Workflow)
1. المستخدم يحدد مشروعًا (أو ينشئ واحدًا).
2. المستخدم يعطي الـ Agent: المشروع + التصميم/المتطلبات (يفضل كملفات `.md` داخل `skills/`).
3. الـ Agent يقرأ السكيل الأساسي + كل سكيلات المشروع.
4. الـ Agent يبني/يكمل الصفحات (`pages/pageNN/...`) وفق سكيلات المشروع.
5. النتيجة تُعايَن وتُصدّر كـ PDF صالح.

## متطلبات عامة لصلاحية PDF (عامة فقط)
- حافظ على قابلية العرض داخل المعاينة والتصدير.
- لا تكسر تخطيط الصفحة أو عناصر التصدير.
- اجعل موارد الصفحة (صور/خطوط) قابلة للوصول ضمن سياق المشروع/التطبيق.
- عند تغيير عدد الصفحات، حدّث `project.json` وأي تسجيل/تحميل يتطلبه التطبيق الحالي.

## ملاحظة توافقية
ملفات توافق الأدوات (مثل `opencode.json`, `CLAUDE.md`, `.github/copilot-instructions.md`) اختيارية وليست المصدر الوحيد. المصدر الأساسي: هذا الملف + `AGENTS.md` + `PROJECT_MAP.md` + سكيلات المشروع المحدد.
